# V0.17.0.239_EA
各位下午好，这里是 Yayin Story Studio 0.17 EA Release版本。自0.16.0以来历经恰好约两个月的漫长开发，我们终于迎来了0.17版本的更新。本次更新包括巨多重大更改，以及大量关键底层问题的修复，是YSS软件迈向通用化和专业化，以及Visindigo框架提供更多功能的重要一步。

由于本次在Visindigo框架上的更新也很重要，因此本次更新日志将会分为两部分，第一部分是YSS软件的更新日志，第二部分是Visindigo框架的更新日志。

值得指出的是，本次更新后，为了能在项目文件中记录更多内容，我们提升了项目的兼容版本（0.1→0.2）。使用此版本YSS打开旧版本项目后（YSS 0.13.0 ~ 0.16.3期间创建的项目），旧版本项目将被自动升级到新的兼容版本，且无法再在旧版本中完全正确的打开。

# YSS 新功能
1. **重要更新** 新增**自由拖放排版与多窗口/多屏幕支持功能**，用户现在可以通过拖拽文件编辑标签页的标签，自由的在本编辑区内对标签进行排序，也可以在本窗口内对其进行自由排版。当拖着标签离开标签区域时，便会显示出排版引导区，将标签在对应的引导区中释放即可完成排版。如果将标签拖拽到窗口外，则会自动创建一个新的窗口，并将该标签放入新窗口中。用户可以通过拖拽标签在不同的窗口之间进行自由移动，支持多屏幕显示和多窗口操作。
2. **重要更新** 新增**YSS MediaPlayer**插件，现在YSS可以播放绝大部分主流音视频格式文件。
3. **重要更新** ASER Studio插件新增**ASER外部资源查看器**，用于以更符合ASER项目的方式展示项目中的资源文件。
4. **重要更新** 为 YSS Installer 新增**崩溃处理和引导功能**，现在YSS在崩溃之后，会以更加详细的方式记录崩溃信息，并自动生成含有全部崩溃信息的压缩包，并在崩溃后将关键信息显示在屏幕上，以便用户反馈。

# YSS 体验优化
1. 文本编辑器的Tab补全列表和悬浮提示现在以液态玻璃效果呈现，以提高程序的整体美观度。
2. 文本编辑器的悬浮提示现在会尝试在显示空间不足时自动改变宽度，以避免提示内容被遮挡。
3. 在文本编辑器有Tab补全列表和/或悬浮提示显示，且用户鼠标距离它们较远的情况下滚动滚轮时，将直接滚动文档本身而非滚动Tab补全列表和悬浮提示。
4. 文本编辑器的悬浮提示现在将在鼠标朝向其运动时保持显示，逃离其运动时自动隐藏。
5. **自由拖放排版与多窗口/多屏幕支持功能**使得YSS统一了文件编辑和工具页面的底层架构，现在用户可以自由的把原本的工具安排到页面中的任何地方，而不仅是底部
6. 暂时将QImage的内存分配上限调整至支持四通道8位色深，最大11000x11000的图片，后期将会进一步优化内存分配方法，以支持更大尺寸的图片。
7. YSS现在会在启动时检测到有插件加载失败的情况下，在显示主页之前弹出提示详细告知用户插件加载失败原因，并同时提供简单的排障建议
8. YSS现在会在项目选择页拉起项目编辑之前，检查项目配置文件是否兼容，以及该项目所必须的插件是否已经正确启用，并在发现错误情况时提供弹窗提示
9. **重要优化** YSS现在会在崩溃后立即尝试存储项目，但不保证一定存储成功。该功能后期会进一步优化，因为我们主要希望在崩溃后将编辑态缓存并在下一次启动后恢复，而非立即硬落盘，以避免在某些极端情况下将错误的数据塞到项目中，反而损坏了原有的项目数据。
10. 优化了文件标签的显示效果，将正在编辑的视觉效果从简单的前缀星号改为一个铅笔图标。此外，现在关闭按钮的显示逻辑也进行了调整，会对当前正在编辑文件始终显示关闭按钮。
11. 重新考虑了ASER Studio捆版资源的方案，以降低YSS运行时的内存占用。
12. 优化了ASER Studio、YSSFileExt中存储文档解析数据的方式，以提高性能。
13. 根据一个底层新功能，优化了YSS内部存储文档错误信息和向前端分发的方式，使得在文档包含大量错误时，消息查看器和计数器的性能显著提升。

# YSS 问题修复
1. 修复了部分极端情况下，YSS Installer和主程序因为更新问题互相把对方卡死的问题。

# Visindigo / YSSCore 新功能
1. **重要更新** 初步提供`Visindigo::Network`网络模块，提供相对更现代化的网络设施交互，并在其中封装了SSE（Server-Sent Events）和WebSocket的功能，方便用户在YSS中使用网络功能。这个模块目前仍处于实验阶段，后续会进一步完善。
2. **重要更新** 初步提供`Visindigo::Agent` AI Agent模块，提供了一个符合现在大多数AI Agent软件所表现出的功能的架构（如MCP Server、Function、Skills、Model Provider、Conversation等），方便用户快速创建支持AI Agent以及AI自动化的应用程序。这个模块目前仍处于实验阶段，后续会进一步完善。（相比Network模块，这个模块目前可预见的还有很多重大API更改，目前根本不推荐在生产环境中使用）
3. **重要更新** 完全重构了`Visindigo::General::PluginManager`，使得其能够在更多平台上以统一逻辑、统一生命周期管理插件。主要新增了`addPluginLoadPath`、`addPluginEntryPoint`两个API，允许手动指定额外加载源和手动挂载入口点，以便在类似安卓这样的平台中从已打包的应用的so库中加载插件。此外，将部分Plugin实例上可以查询到的信息（如插件的配置文件就等）在PluginManager中也提供了查询接口。
4. **重要更新** 为`Visindigo::General::Plugin`增加了手动指定非插件依赖项目（DependLibs）的功能，允许插件加载不是Visinidgo插件的第三方动态链接库。这使得插件可以更自由的引入第三方库，而不必将其打包为Visindigo插件。
5. **重要更新** 重构了`Visindigo::General::Exception`，并新增了`Visindigo::General::CrashGateway`，在Visindigo框架中统一处理从Qt事件循环捕获的Visindigo异常、C++异常，以及从操作系统处响应的未捕获异常。重新考虑了Exception类的设计以减少其在异常处理中的开销以及内存不安全性。
6. 为`Visindigo::General::Plugin`提供了插件二进制文件夹语义，以便插件访问存放自己二进制的文件夹。
7. 新增`Visindigo::Utility::FileOperation`，将原有的`Visindigo::Utility::FileUtility`中部分文件/文件夹操作的功能拆分出来，并提供详细的返回信息而并非原本那样静默吞掉错误。FileUtility中的原有函数并未直接删除，但已经在内部重新路由到FileOperation中。
8. 几乎重新实现了`Visindigo::Widgets::LiquidGlassEffect`，现在额外提供色散、边缘光、全局光效果，已更好还原Apple在其系统中所用的相关设计。此外还引入了透明度设置，以便合并`QGraphicsOpacityEffect`提供的效果，还提供了快捷函数直接操作目标QWidget的QPalette中的背景颜色透明度。此外，大幅提升了性能，现在基本可用于各种背景为动态的场景。
9. 初步引入权限系统，尝试为Visindigo应用提供统一的权限声明和授权接口，将在0.18中进一步开发
10. `Visindigo::General::Version`现在支持对两段式版本号进行解析。但输出时仍然至少按三段式进行输出。
11. `YSSCore::Editor::FileServer`现在合并了原本属于ToolWidget的语义，现在允许将FileServer `listAsTool`，以声明其提供的`Virtual FileEditWidget`被视作工具使用，不与特定实际文件绑定。因此原本有关ToolWidget的API被全部弃用。
12. `YSSCore::General::YSSProject`现在提供了必须插件语义，以及项目缓存文件夹的访问
13. `YSSCore::Editor::TextEdit`现在提供`ICustomDocumentData`以允许用户在`QTextDocument`中存储自定义数据。和Qt提供的CustomData不同的是，此接口在内部由一个新的YSSCore内部设施管理，允许不同的源在同一个QTextBlock内存储自己的数据而互不干扰。这有助于利用RAII的方式在文档中存储自定义数据，而不必担心在文档被销毁时忘记清理数据。根据此功能，重构了DocumentMessage的保存方式，并弃用了DocumentMessageCenter。

# Visindigo / YSSCore 问题修复
1. 本次对`Visindigo::General::PluginManager`进行的重构至少修复了以下问题：
    - 修复了PluginManager在此前版本中，不能正确处理级联依赖的问题，现在改用拓扑排序而非简单计数来处理依赖顺序
    - 修复了插件的MetaDataLoaded阶段实际上从未被正确设置的问题
    - 修复了在加载插件途中，对于中途加载失败且可从内存中卸载的项目，其内存释放代码从未生效的问题
    - 修复了部分信息查询函数，文档中给定的范围限定语义和代码实际实现的限定语义不一致的问题
    - 修复了部分环节的LoadResult所写值不能正确反映加载结果的问题
2. `YSSCore::General::YSSProject`现在在内部改用QFileInfo索引项目路径，以缓解几个使用中的潜在路径不一致问题。
3. 回退了0.16中对`Visindigo::Widgets::Terminal`做出的优化，因为优化的实现有误。
4. 修复了`VICopyable_Impl`宏实现有误，未按C++标准处理move-from语义，造成潜在的访问空指针的问题
5. 重新考虑了`Visindigo::General::LogCenter`的构造-析构-单例获取函数设计，此前它未导致问题，但因逻辑奇怪，仍然进行了重构。
6. 修复了`Visindigo::General::Version`在比较大小时未满足单调性的问题，引起在QMap或其他类似的容器中使用时可能出现的异常行为，以及导致API/ABI兼容判断函数的返回值在某些情况下不正确的问题。

# 下一阶段开发计划（0.17.1/0.18）
目前，由于在0.17正式发布前，我们反复通过各种AI Agent对底层代码进行了扫描，因此目前主要针对代码逻辑上的问题进行了大量修复和优化，但仍然欠缺对实际业务逻辑的考察，因此可能很快因为一些业务逻辑上的漏洞而更新0.17.1版本。此外，目前不打算在0.17维护过程中继续添加新功能，因此主线将很快转入0.18版本的开发。

我们在Beta1的开发计划中已经提到，0.17中存在一些没有继续开发的内容，除了上面提到的Network和Agent模块这两个重量级内容之外（这两个模块至少要到0.19甚至0.20才能完成），还有如插件权限管理、敏感设备访问提示（主要是定位、摄像头、音频、麦克风）、项目文件打开偏好记录，YSS受支持文件扩展名清单和打开优先级顺序，首选打开方式等需要在0.18中继续开发的内容。显然，这些内容的缺失并不影响YSS目前的使用，但全部添加之后会给用户带来更好的体验。0.18目前计划在2026年12月初发布。
